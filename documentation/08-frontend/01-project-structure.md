## 1. Overview

The LocalMind frontend project follows the standard structure generated by Angular CLI with the following architectural customizations:

- **Standalone Components**: no NgModule; each component declares its own dependencies.
- **Feature-based organization**: each feature is isolated in a dedicated directory under `features/`.
- **Core/Shared pattern**: singleton services in `core/`, reusable elements in `shared/`.
- **Lazy loading**: each feature is a separate bundle loaded on-demand.

## 4. src/app Directory

### app.ts (Root Component)

The root component of the application. It is a standalone component that contains the main `<router-outlet>`.

```typescript
@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet],
  template: '<router-outlet />'
})
export class AppComponent {}
```

### app.config.ts (Application Providers)

Configures application-level providers using the new function-based Angular API:

```typescript
export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes, withComponentInputBinding()),
    provideHttpClient(withInterceptors([errorInterceptor])),
    provideAnimations()
  ]
};
```

| Provider                        | Description                                                        |
|---------------------------------|--------------------------------------------------------------------|
| `provideRouter()`               | Configures the router with routes defined in `app.routes.ts`       |
| `withComponentInputBinding()`   | Enables automatic binding of route params to `@Input()` properties |
| `provideHttpClient()`           | Configures `HttpClient` with interceptors                          |
| `withInterceptors()`            | Registers functional interceptors (error interceptor)              |
| `provideAnimations()`           | Enables the Angular animations system                              |

### app.routes.ts (Root Routes)

Defines the main route configuration with lazy loading for each feature. See `02-routing-lazy-loading.md` for detailed documentation.

## 5. core/ Directory

The `core/` directory contains singleton services, interceptors, and shared models at the application level. These elements are instantiated once and available everywhere in the application.

### core/interceptors/error.interceptor.ts

Functional HTTP interceptor that handles API call errors in a centralized way:

- Catches HTTP errors (4xx, 5xx).
- Logs errors to the console.
- Propagates the error for component-level handling.

### core/services/api.service.ts

Base service for API calls. Provides:

- Base URL configured via environment file (`environment.apiBaseUrl`).
- Helper methods for building complete URLs.
- Integration with `HttpClient`.

### core/models/api-response.model.ts

TypeScript interfaces for API responses:

- `ErrorResponse`: interface for the standard error format (`status`, `message`, `timestamp`, `path`).
- Generic interfaces for paginated responses (planned).

## 6. shared/ Directory

The `shared/` directory contains reusable elements across different features: pipes, directives, generic UI components.

### shared/pipes/file-size.pipe.ts

Standalone pipe for formatting file sizes in a human-readable format:

- Input: `number` (bytes).
- Output: formatted `string` (e.g., `2.5 MB`, `512 KB`, `1.2 GB`).
- Standalone: can be imported directly into components.

## 7. layout/ Directory

### layout/layout.component.ts

Application shell component that defines the main visual structure:

- **Sidebar**: side navigation with links to features (Chat, Documents, Search, Folders, Settings, Dashboard).
- **Content area**: `<router-outlet>` for rendering feature components.
- **Header** (optional): top bar with title and context information.

The `LayoutComponent` is used as a parent component in the route configuration: all features are loaded as child routes of the layout.

## 8. features/ Directory

Each feature is organized in a dedicated directory with the following internal structure:

```
features/{feature-name}/
+-- {feature-name}.routes.ts    # Feature route definition
+-- models/                     # Feature-specific TypeScript interfaces
+-- services/                   # Feature-specific HTTP services
+-- state/                      # Signal-based stores (if needed)
+-- pages/                      # Page components (smart components)
+-- components/                 # UI components (dumb components, if needed)
```

### Implemented features

| Feature     | Path        | Sub-directories                       | Description                          |
|-------------|-------------|---------------------------------------|--------------------------------------|
| Chat        | `/chat`     | routes, models, services, state, pages| Chat with LLM, most complete feature |
| Documents   | `/documents`| routes, models, services, pages       | Document management                  |
| Search      | `/search`   | routes, pages                         | Semantic search                      |
| Folders     | `/folders`  | routes, pages                         | Folder configuration                 |
| Settings    | `/settings` | routes, pages                         | LLM settings and API keys            |
| Dashboard   | `/dashboard`| routes, pages                         | Health check and statistics           |

## 9. environments/ Directory

### environment.ts (Development)

```typescript
export const environment = {
  production: false,
  apiBaseUrl: 'http://localhost:8080/api/v1'
};
```

- Used during `ng serve`.
- Points directly to the Spring Boot backend running on port 8080.

### environment.prod.ts (Production)

```typescript
export const environment = {
  production: true,
  apiBaseUrl: '/api/v1'
};
```

- Used during `ng build --configuration=production`.
- Relative URL: assumes that frontend and backend are served from the same origin (reverse proxy).

## 11. Conventions

### Naming

| Type              | Convention                     | Example                            |
|-------------------|--------------------------------|------------------------------------|
| Components        | `kebab-case.component.ts`      | `chat-page.component.ts`           |
| Services          | `kebab-case.service.ts`        | `chat.service.ts`                  |
| Models            | `kebab-case.model.ts`          | `chat-message.model.ts`            |
| Pipes             | `kebab-case.pipe.ts`           | `file-size.pipe.ts`                |
| Interceptors      | `kebab-case.interceptor.ts`    | `error.interceptor.ts`             |
| Routes            | `kebab-case.routes.ts`         | `chat.routes.ts`                   |
| Stores            | `kebab-case.store.ts`          | `chat.store.ts`                    |

### Component organization

- **Page components** (smart): components that interact with services and manage state. Located in `pages/`.
- **UI components** (dumb): presentational components that receive data via `@Input()` and emit events via `@Output()`. Located in `components/`.
- **All components are standalone**: there are no NgModules in the project.

### Imports

Each standalone component explicitly declares its own dependencies in the `imports` array:

```typescript
@Component({
  standalone: true,
  imports: [CommonModule, FormsModule, RouterLink, FileSizePipe],
  // ...
})
```
